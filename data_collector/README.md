# FR3 遥操作数据采集与训练数据导出

采集和导出是两个独立步骤。采集器按目标每秒一百个控制周期保存实测机器人状态和已提交的关节目标，同时保存两台相机每秒三十帧的彩色视频。导出器按文件中的真实时间戳重新采样，默认生成每秒三十帧的 LeRobot 第三版数据；改用每秒十五帧时无需重新采集。

## 启动与采集

先分别启动机器人服务、夹爪服务和关节控制节点：

```bash
bash frankateleop/1_launch_robot.sh
```

```bash
bash frankateleop/2_launch_gripper.sh
```

```bash
bash frankateleop/3_launch_node.sh
```

这些命令应在三个终端中依次启动，并保持运行。采集器和控制节点必须在同一台主机上，才能共用主机单调时钟。采集期间不要同时运行其他占用相机或遥操作节点的程序。

编辑 [collect_task.sh](collect_task.sh) 中的任务名称、任务说明、训练集条数、验证集条数、操作者、会话、两台相机序列号及目标控制频率，然后运行：

```bash
bash data_collector/collect_task.sh
```

脚本当前为新任务 `stack_bowl` 规划训练集八十条、验证集二十条，共一百条。验证集每五条计划出现一次。开始其他新任务时，先修改任务名称、说明和采集条数。已有任务的计划在创建后固定；继续已有任务时，脚本中的任务名称和两类条数必须与原计划一致。

已有的 `stack_bowl` 任务目录使用旧原始格式。示例脚本使用新的 `stack_bowl` 任务名称，以免把两种格式混入同一份清单。

程序先让操作者手动对齐主手和机器人，再持续进行遥操作。空闲时查看终端打印的两张相机预览图，按 `s` 开始一条记录；录制时按 `t` 保存并标记操作者认为成功，按 `i` 丢弃并重试；空闲时按 `q` 退出。按 `t` 保存且原始数据写入完整后，即可直接导出。清单中保留的验收字段不影响导出。

相机准备完成后，控制线程会重新检查主手与机器人是否对齐，并根据本次实测关节位置逐步接近主手目标。启动过渡期间，每次提交的关节目标与本次实测位置的最大差值为 0.05 弧度。完整主手目标获得关节控制接口确认后，程序才显示采集按键提示。实测状态无效、任一关节差值超过 0.30 弧度，或过渡超过十秒时，程序停止启动。

采集器使用主手驱动程序的符号、偏置及启动时角度分支，然后根据机器人描述文件中的关节限位裁剪目标。启动过渡完成后，控制线程用两级时间滤波逐步追随主手，每级时间常数为 0.03 秒，并将每个关节的目标变化速度限制在每秒 1.5 弧度。这样主手读数即使在相邻控制周期之间跳变，提交给机器人的目标也会连续变化。控制节点回传实际提交给关节控制接口的目标和提交时间，原始记录保存该目标。夹爪命令采用从零到一的开口比例：零为闭合，一为完全张开；变化不足百分之一或距离上次排队不足五十毫秒时沿用上次目标。夹爪命令排队成功不等于夹爪已经运动到位。

## 原始数据

`data/raw/任务名称/` 下有任务级配置和采集清单。每条记录位于 `episode_000000` 形式的独立目录，包含：

```text
metadata.json
summary.json
checksums.json
robot.hdf5
head_camera/color.mp4
head_camera/frames.jsonl
left_wrist_camera/color.mp4
left_wrist_camera/frames.jsonl
```

`robot.hdf5` 的每一行对应一个控制周期。`timestamps/control_cycle_id` 保证周期编号连续；`timestamps/observation_ns` 是实测状态返回采集器时的主机单调时间，`timestamps/command_ns` 是控制节点收到关节命令确认后的主机单调时间。机器人服务可能返回缓存状态，因此前者不被解释为机器人内部的精确测量时间。设备原生计数如可获得，会保存在附加时间字段中。

`observations/` 保存七个实测关节位置、七个实测关节速度、夹爪实际宽度和从实测关节计算的末端位姿。`actions/` 保存真正提交的七个目标关节位置、目标夹爪开口比例和由目标关节重新计算的末端位姿。位姿使用机器人底座到 `fr3_link8` 坐标系的位置及按 `x, y, z, w` 排列的四元数；六维旋转表示按旋转矩阵的前两列顺序排列。

读取失败、发送失败或控制周期错过时，采集器保留该行和有效性标记，缺失数值为无效值，不用前值填补。`diagnostics/command_status` 的数值含义为：零表示未发送，一表示关节控制接口已确认，二保留给明确接口报错，三表示调用后无法确认状态。原始记录不会保存主手原始读数。

每台相机的 `frames.jsonl` 与视频逐帧对应，包含连续的视频帧编号、主机收到帧的时间、设备时间及其单位和时钟域、设备帧序号和有效性标记。原始视频使用无损编码；写入完成后会逐帧解码并核对像素。

## 导出训练数据

任务清单中 `success=true` 且有原始记录编号和路径的记录可直接进入正式导出，无需人工验收。`acceptance_status` 和 `accepted_episode_id` 是兼容旧清单的字段，导出器不读取它们。按 `i` 丢弃或标记失败的记录不会导出。导出时仍检查原始文件完整性、时间对齐和运动数据；检查未通过的记录会使导出失败。`--preview-episodes` 可用于只导出前几条符合条件的记录。

```bash
bash data_collector/convert_task.sh \
  --manifest /home/pnp/yzx/data/plans/stack_bowl_manifest.csv \
  --output /home/pnp/yzx/data/lerobot_v3/stack_bowl \
  --fps 30 \
  --openwam-python /home/pnp/miniconda3/envs/lerobot/bin/python
```

导出器建立 `t[k] = t0 + k / fps` 时间轴。实测状态选最近的有效值，关节位置命令按提交时间零阶保持，图像选最近的有效帧。导出器在选择目标关节后重新计算目标末端位姿。状态和动作都是十维：位置三维、旋转六维、归一化夹爪一维；夹爪数值为负一表示闭合，正一表示完全张开。

导出器默认在一个采样周期内调整每条记录的采样起点，使机器人状态、夹爪状态和两台相机的最大时间差尽量小，无需增加额外参数。调整可能使一条记录少导出一帧；命令仍只选目标时间之前已确认的值，并遵守最大保持时间。质量报告记录实际调整量和减少的帧数。原始相机帧是离散采集的，时间差无法通过导出变成零。

`alignment_audit.parquet` 记录每帧选择的控制周期和相机帧以及时间差。`quality/episode-*.json` 记录缺失数、状态与命令的时间差分布、保持时长、相机对齐误差、掉帧、关节跳变和运动学一致性。`quality_report.json` 记录导出文件可读性及 OpenWAM 读取结果。带有 `--openwam-python` 时会使用指定解释器实际读取一条双相机样本；未指定且当前环境缺少视频读取依赖时，报告会明确写为未运行。

目标目录必须不存在。导出失败时保留带有 `.partial-` 后缀的目录，以便检查失败原因。原始目录始终保持独立，可再次按不同采样频率导出。
