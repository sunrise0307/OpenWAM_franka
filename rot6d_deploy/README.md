# FR3 绝对末端位姿部署

本目录提供机器人端的完整接入代码。程序连接 OpenWAM 服务，读取两路彩色相机和机器人实测状态，获取十维绝对目标，再交给持续运行的末端笛卡尔阻抗控制器。代码只在本目录内，未修改服务端或现有遥操作程序。

## 代码分工

| 位置 | 作用 |
| --- | --- |
| `policy/cameras.py` | 持续采集头部和左腕部彩色图像，只保留最新帧，并检查图像是否过期。 |
| `policy/client.py` | 编码图像，建立 WebSocket 连接，核对服务元数据；每次发送一份观测，按服务端配置校验返回动作的数量和内容。请求失败后不会自动重发。 |
| `control/geometry.py` | 将六维旋转表示正交化，再转换为机器人使用的四元数；转换夹爪宽度与开合值。 |
| `control/cartesian_policy.py` | 在机器人控制周期内平滑跟踪目标、计算末端位姿误差；目标更新超时时锁定当时的实测位姿。 |
| `control/robot.py` | 执行机器人预设的回零动作，读取实测位姿，启动控制器，提交完整的绝对目标，控制夹爪，并处理目标超时。 |
| `main.py` | 启动时回零；按顺序提交每组全部动作，待本组执行结束后重新采集观测并请求下一组。 |
| `runtime.py` | 统一选择机器人控制依赖的编译目录，并在连接设备前验证库能正常加载。 |
| `check_dataset.py` | 离线对照转换后的动作、状态与原始机器人记录。 |

## 位姿和时间约定

服务动作与实测状态都是十个数：前三个是机器人基坐标系中的位置，接着六个是 `fr3_link8` 旋转矩阵前两列，最后一个是夹爪开合值。位置单位是米；夹爪取值为负一到正一，其中负一表示闭合。机器人夹爪接口使用零到一，因此控制代码会做转换。姿态四元数按 `x、y、z、w` 排列。

服务给出的动作是**绝对目标**。控制代码不会把目标位置加到实测位置上，也不会截短通过校验的绝对目标。六维旋转表示若包含非有限数、零方向或平行方向，会被拒绝。控制代码还会检查任务工作空间、目标和实测位姿之间的距离。

采样记录使用的夹爪最大宽度为 `0.07982299476861954` 米。实测夹爪宽度与模型开合值按这个宽度相互转换；如果机器人报告的最大宽度小于这个值，程序会拒绝启动。这样发送给模型的夹爪状态与采样时保持相同的数值约定。

机器人硬件配置的控制周期为每秒一千次。服务端按启动参数决定每条响应包含多少个动作；每个动作仍是十个数。客户端核对服务元数据中的动作数量、响应声明的数量和实际数组行数，再按服务端给出的动作间隔逐行提交绝对目标。首组请求使用回零后的图像和实测状态。之后每组都先提交全部动作，并等待最后一个动作运行完整的动作时段；本组结束后，客户端重新采集图像和实测状态，再发送下一次请求。每组只发一次请求。

机器人端在每个控制周期更新内部参考位姿，并持续计算末端位姿误差和力矩。内部参考位姿的默认平移速度上限为每秒 `0.8` 米，转动速度上限为每秒 `2.5` 弧度。数据中最大的相邻目标位移和转角分别需要约 `27` 毫秒才能走完，因此控制器可以在正常的三十三毫秒目标间隔内完成参考位姿更新。实际机械臂是否到达目标还取决于阻抗增益、负载和环境。

每次启动控制程序，策略服务、相机和机器人连接完成后，机械臂先执行机器人服务预设的关节回零动作。程序等待回零结束，检查回零位置处于填写的工作空间内、机器人没有报告错误，并要求最终各关节与预设位置的最大偏差不超过 `0.05` 弧度。回零动作最长等待三十秒。任何检查失败都会停止启动，首个观测请求和策略动作都不会发出。回零只在程序启动时执行一次，不在每组动作之间重复。

一组动作的时长由服务端返回的动作数量和动作间隔决定，不固定动作行数。例如服务端返回三十二行、每秒执行三十行时，一组约需 `1.067` 秒；这三十二行全部执行完毕后，程序才重新采集观测并请求下一组。下一组使用的是上一组结束后的新图像和实测状态。

组末额外等待默认是零。`--batch-pause-s` 可选地在最后一个动作时段结束后、重新采集观测前增加等待。推理期间，控制器继续跟踪并保持上一组的最后目标。连续五秒没有新目标时，机器人端控制器会锁定当时的实测位姿；客户端的定时检查还会终止自有控制器，让机器人服务切换到默认的当前位置保持控制器，并停止本次运行。若推理和可选等待使目标更新超时，运行会因此停止。可用 `--target-timeout` 调整超时值，用 `--max-linear-velocity` 和 `--max-angular-velocity` 调整内部参考位姿的速度上限。每组运行日志会显示图像编码完成后至服务端返回的耗时、目标与本组所用观测的最大差距、实际移动量、组结束时与最后一个目标的差距，以及观测位置、首尾目标位置和组内目标变化范围。

## 运行前条件

1. 启动 Polymetis 机器人服务与夹爪服务。默认端口分别为 `50051`、`50052`。程序要求机器人服务报告七个关节、`fr3_link8` 末端以及每秒一千次控制周期。
2. 停止原遥操作节点和其他正在运行的机器人控制器。程序发现已有自定义控制器时会拒绝启动。
3. 启动与本任务匹配的 OpenWAM 服务。程序会检查绝对目标、坐标系、十维状态、旋转顺序、动作间隔，以及每条动作响应中的行数与服务端配置是否一致。
4. 确认两台相机的序列号，并根据实物环境填写可用工作空间的上下界。程序不会自行推断桌面、物体或相机的位置。

在已经配置好 Polymetis 的 Python 环境中，安装 `requirements.txt` 所列依赖。从 `/home/pnp/yzx` 目录执行；程序会按本项目机器人启动脚本使用的 `build_eef` 目录统一配置 Python 模块与编译库，并在连接策略服务和机器人前用独立进程检查加载结果。不要在同一进程中混用本项目的 `build` 和 `build_eef` 编译库。

```bash
python -m rot6d_deploy.main \
  --execute \
  --policy-url ws://策略服务地址:8848 \
  --robot-host 127.0.0.1 \
  --head-serial 头部相机序列号 \
  --wrist-serial 腕部相机序列号 \
  --prompt 'Stack the two pink bowls in the center of the table.' \
  --workspace-min 最小横坐标 最小纵坐标 最小高度 \
  --workspace-max 最大横坐标 最大纵坐标 最大高度
```

工作空间数值必须用实测并确认过的米数替换。程序只检查边界数值有效、最小值小于最大值，并在运行时检查实测位置和目标位置是否落在所填范围内；不会再与未经核实的固定边界比较。`--execute` 是启动实际机器人连接的显式开关。不设置 `--max-steps` 时，每条响应中的动作都会按顺序提交；显式设置这个动作总数上限时，最后一组可能只执行前几行。按下中断键、网络报错、相机失效或目标校验失败时，程序都会释放自有控制器。夹爪目标最多每五十毫秒提交一次，夹爪反馈用于下一次实测状态。

## 离线检查

在项目根目录执行：

```bash
python -m unittest discover -s rot6d_deploy/tests -v
```

测试覆盖旋转转换、退化输入、完整绝对目标提交、控制器逐周期平滑跟踪和超时保持、服务元数据、不同数量的动作响应、逐个提交的节奏、组末重新采集观测并请求下一组、可选的组末等待，以及显式动作上限造成的最后一组截取。测试需要使用已配置好的机器人控制环境，使本地机器人模型与编译库可导入。

再运行采样数据核对：

```bash
python -m rot6d_deploy.check_dataset
```

检查器只读取 `data/lerobot_v3/stack_bowl` 和 `data/raw/stack_bowl`，根据对齐记录中的控制周期编号找到原始位姿与夹爪数据；报告写入 [dataset_check_report.json](dataset_check_report.json)。已检查全部 `100` 段、`70,969` 帧：位置最大差异为 `4.21×10⁻⁸` 米，六维旋转各分量最大差异为 `2.99×10⁻⁸`，还原四元数后最大转角差异为 `5.17×10⁻⁸` 弧度，夹爪开合值最大差异为 `2.99×10⁻⁸`。这属于单精度存储造成的舍入误差。所有目标都满足程序默认的实测位姿距离与转角限制。采样数据中相邻目标最大位移为 `0.020874` 米，最大转角为 `0.065815` 弧度；旧的单次更新限幅分别会截短 `15,841` 次位移更新和 `19` 次转角更新，现已改为机器人控制周期内平滑跟踪完整目标。

这些都是离线数值核对，没有启动实体机器人，也没有验证相机标定或真实抓取效果。之前测得的 `1.17` 秒是旧接口连续请求八次的耗时，不能用来估计新接口单次请求的推理时间。
